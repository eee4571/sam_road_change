# SAMRoad 一键道路变化检测（独立用户项目）

本目录可单独运行和迁移。运行时只使用本目录内部的代码、模型、配置、环境和输出，不访问父目录，也不包含模型训练功能。

面向地信生产的默认流程是：**新建或打开项目，连接一个或多个外部原始数据目录，扫描并确认映射，然后点击“运行完整流程”**。项目目录只保存 `project_config.json`、任务状态、日志和成果；外部 SHP、TXT 与影像不会被移动、复制或重命名。变化真值不再作为运行前的任务模式；道路和变化成果生成后，在“成果与评价”页自动匹配项目真值并运行精度评价。程序会自动完成：

1. 在模型启动前解析全部期次 TXT，并检查每张影像能否打开、CRS、波段和数据类型；
2. 将各期影像重投影并裁切到同一验证区分析网格，再提取道路图结构和道路面、计算中心线宽度并导出 GPKG/SHP；
3. 校验并固化真实日期顺序，执行 `n-1` 个相邻期次变化检测，并在启用评价时使用对应真值计算指标；
4. 汇总变化矢量、评价指标和任务索引，并生成可直接打开的成果目录；
5. 在任务完成后，从 GUI 直接打开成果目录、长时序 SHP、属性表、总精度文件和任务报告；结果页不再加载 PNG 预览图。

完整多期任务结束后，程序还会在每个验证区/格网的 `05_长时序成果` 目录自动生成纯 Shapefile 长时序成果：

- `road_life.shp`：道路生命周期主成果，一条稳定道路段一行；属性表含跨期稳定 `road_id`、首次/最后存在期次、各期状态/宽度/置信度以及相邻期事件码；
- `road_obs.shp`：一条道路段×一个期次一行的状态明细；
- `road_event.shp`：新增、消失、拓宽、变窄及不确定转换的道路事件线；
- `event_parts.shp`：关联 `road_id` 和 `event_id` 的实际变化面片；
- `road_lineage.shp`：为后续道路分裂、合并和延伸关系保留的兼容层；位置改变不会建立改线关联；
- `road_review.shp`：跨期匹配不确定、需要复核的道路段。

以上每份 SHP 均配套输出 `.shx`、`.dbf`、`.prj` 和 `.cpg`。查看某条道路在哪些年份存在、何时消失或发生宽度变化时，优先打开 `road_life.shp`；进行程序化长时序统计时使用 `road_obs.shp` 和 `road_event.shp`。

旧的格网目录方式仍然保留，但放在 GUI 默认收起的“备用选项：格网目录模式”中，需要显式展开并选择。

## 默认输入：验证区项目

面向业务人员的数据摆放模板、TXT 清单写法、影像/真值约束和大影像注意事项，见 [`数据输入组织说明.md`](数据输入组织说明.md)。正式批量运行前建议先按其中的“提交前检查表”核对一次。

默认模式以多个验证区文件夹为任务单元。每个验证区文件夹需要两类必填数据，另有一类可选评价数据：

1. **验证区范围**：该文件夹下一个带 CRS、非空的面状 Shapefile（`.shp`，并附齐同名 `.shx/.dbf/.prj`）；
2. **区内多期影像**：至少两个“期次 + TXT”，每个 TXT 内逐行列出该验证区该期的实际影像路径；
3. **变化真值（结果阶段可选）**：完成变化检测后，在“成果与评价 → 精度评价”中使用第一步已经保存的相邻期次真值；缺少时可“补充真值”并自动写回项目配置。评价直接复用已有 `road_changes.gpkg`，不会重新运行道路提取或变化检测。

各期影像外边界不必相同。程序在模型启动前先检查 TXT 中的每张影像是否可打开，不再预先扫描整幅影像的全部有效像元。通过元数据检查后，程序依据真实验证区 Polygon/MultiPolygon 生成窗口，只读取与窗口相交的源影像；L 型验证区外包矩形的空白角落不会生成推理任务。验证区外像元及偶发的小范围未覆盖像元写为 NoData 并继续，整期在验证区内完全没有有效数据时才停止。规范化结果保存在带输入指纹的窗口目录中，中断重跑会复用已完成窗口。

GUI 中先填写期次名称并完成生产检测；结果页会按自然顺序列出已有相邻变化对。选择其中一组及对应真值即可评价，程序不跨期跳跃。

两个验证区的命令行等价示例（各区可以使用不同年份）：

```powershell
env\samroad_env\python.exe 面向用户\user_pipeline.py all `
  --validation-area north D:\project\north\01_验证区\boundary.shp `
  --period north 2021 D:\project\north\02_影像\2021.txt `
  --period north 2022 D:\project\north\02_影像\2022.txt `
  --truth north 2021 2022 D:\project\north\03_变化真值\2021_to_2022.shp `
  --validation-area south D:\project\south\01_验证区\boundary.shp `
  --period south 2020 D:\project\south\02_影像\2020.txt `
  --period south 2023 D:\project\south\02_影像\2023.txt `
  --truth south 2020 2023 D:\project\south\03_变化真值\2020_to_2023.shp `
  --output-root 面向用户\outputs `
  --checkpoint 面向用户\models\samroad\samroad.ckpt `
  --config 面向用户\config\samroad_inference.yaml
```

无真值生产模式在同一命令中增加 `--no-evaluation`，并省略全部 `--truth` 参数。

## 面向大批量任务的运行保障

- 可直接点击“运行完整流程”；正式任务会先解析所有 TXT，并核验每张影像能否打开、CRS、波段、数据类型、影像数量、公共分析网格、模型与配置、CPU/CUDA 环境和磁盘空间，检查失败时不会启动模型；错误会定位到期次、TXT 行号、检测编码和影像路径；
- 验证区规范化采用 4096 像素窗口流式重投影和镶嵌，不再把完整多波段验证区一次性放入内存；
- 规范化按窗口保存完成状态和输入指纹，异常退出后只重试未完成或输入已变化的窗口；
- GUI 显示总工作单元进度、已用时、预计剩余时间和当前规范化窗口；
- 每完成一个期次或变化对都会原子更新 `job_state.json` 和 `pipeline_result.json`；
- 取消或异常退出后，再次点击“运行完整流程”即可自动继续当前活动任务；完整且输入未变化的阶段会复用，输入或参数变化时只失效相关阶段；
- 默认允许单项失败后继续其他格网，失败和依赖跳过项记录在 `task_report.csv`、`task_report.json`；
- GUI 完整日志写入输出根目录的 `_logs/<任务名称>.log`，界面只保留最近 2000 行，避免长任务拖慢窗口；
- 连接规范数据目录后可自动识别每个验证区子文件夹内的 `01_验证区/02_影像/03_变化真值`；项目路径、外部数据路径、映射和当前活动任务自动原子保存到项目目录的 `project_config.json`，旧任务配置 JSON 仍可在高级设置中导入/导出。
- “导出诊断包”会打包任务索引、报告、日志和运行环境摘要，不包含原始影像或模型，便于提交问题。

多验证区项目以“项目根目录/验证区文件夹”为单元，每个验证区文件夹分别包含自己的 `01_验证区`、`02_影像` 和 `03_变化真值`，可以拥有不同年份组合。结果阶段默认按实际真值字段 `BHBM` 评价：`2=新增`、`3=变化`、`4=灭失`，其中预测的拓宽和变窄都会合并为“变化”。程序重点报告“全部变化区域查全率”和“新增/变化/灭失判断正确率”，同时保留各类别 Precision、Recall、F1 和 IoU 明细。点击“评价全部并汇总”会跨全部验证区和各区相邻期次生成 `evaluation_summary.csv/json`。中心线平均偏移只评价已经空间匹配的新增、灭失对象；同一真值道路面对应双线预测时，先合并为一个道路走廊再提取代表中心轴。未检出的对象由查全率反映，不混入位置偏移；`BHBM=3` 的变化面不能唯一确定道路中心线，因此明确排除。

## 备用输入：格网目录

需要兼容传统地信格网组织方式时，展开 GUI 的备用选项并选择“使用旧格网目录模式”：

```text
格网数据根目录/
├─ area_01/
│  ├─ 2021.txt
│  ├─ 2022.txt
│  └─ 2023.txt
├─ area_02/
│  ├─ 2021.txt
│  └─ 2022.txt
└─ province_shp/       可保留，生产推理时自动忽略
```

每个 `<期次>.txt` 每行填写一张该期原始影像的本地路径、映射盘路径或 UNC 路径。支持 UTF-8、UTF-16 和 GB18030 编码。每个格网至少需要两个期次。格网备用模式沿用旧行为，不要求验证区和变化真值。

也支持以下两种简化结构：

```text
area_01/2021.tif
area_01/2022/*.tif
```

影像格式支持 GeoTIFF、IMG、JP2、VRT、PNG、JPG；推荐使用带 CRS 和仿射变换的 GeoTIFF。同一 TXT 可包含多张影像。

## 相邻期次变化检测规则

期次名称支持 `YYYY`、`YYYYMM`、`YYYYMMDD` 和 `YYYY-MM-DD`，按真实日期而不是扫描顺序排列，并在正式运行前弹窗展示最终期次顺序和相邻变化对。例如包含 `2021、2022、2024` 时自动检测：

- `2021 → 2022`
- `2022 → 2024`

默认验证区模式对一个验证区项目逐对检测；格网备用模式则让每个格网独立检测，不会把不同格网的道路错误配对。变化成果包括新增、灭失、拓宽、变窄等分类结果。

变化检测采用“跨期中心线匹配 → 局部宽度比较 → 公共轴线 → 标准化 Buffer 路面 → 新增/灭失/拓宽/变窄”。`road_surfaces.shp` 继续作为真实路面用于展示、人工检查、测宽和质量佐证，但不再直接以两期不规则真实路面的裸差集作为最终变化面。

每期正式中心线在端点、路口和已有宽度变化位置保留分段，剩余长线按约 15 米分段，形成 `road_width_segments.shp`；局部宽度使用现有断面和宽度段的中位数/MAD稳健汇总，路口、边界、不对称、异常及 C 级断面不进入自动宽变统计。`road_corridors.shp` 是这些局部中心线按半宽、平头圆角 Buffer 后的标准化道路走廊，专供变化检测使用。

跨期匹配使用 STRtree 生成局部候选，再综合双向长度覆盖率、中位距离、方向、端点、长度比例和拓扑关系验证；空间候选未通过方向/距离/重合检查时不能参与前后覆盖计算。匹配支持一对一、一对多、多对一和部分匹配，并输出 `road_matches.shp`。可靠匹配道路使用质量较高的中心线，或对质量相近的两期中心线沿归一化里程加权平均，生成仅供比较的 `canonical_roads.shp`。偏移超过容差时不建立公共轴线，而是把前期完整未匹配段标为灭失、后期完整未匹配段标为新增，不产生“改线”类别或宽度变化。

宽度变化仅在公共轴线上比较两期局部 Buffer。默认同时要求绝对宽差不少于 2 米、相对宽差不少于 20%、连续变化长度不少于 20 米、有效断面比例不少于 60%、同方向变化断面比例不少于 70%；C 级宽度不能自动产生宽变。拓宽面为后期走廊减前期走廊，变窄面反之。新增和灭失使用未匹配道路段的完整局部宽度 Buffer；每期真实有效像元范围的交集会参与裁切，NoData、验证区外和镶嵌空洞不会产生确定灭失。

## 输出结构

每次点击会创建独立任务目录，避免覆盖历史成果：

```text
outputs/
├─ latest_pipeline.json
├─ _logs/<任务名称>.log
└─ run_YYYYMMDD_HHMMSS/
   ├─ job_state.json
   ├─ pipeline_result.json
   ├─ task_report.csv
   ├─ task_report.json
   ├─ validation_inputs/       默认验证区模式的统一分析栅格
   └─ grids/
      └─ validation/           格网备用模式中为实际格网名
         ├─ periods/
         │  ├─ 2021/.../products/roads.gpkg
         │  └─ 2022/.../products/roads.gpkg
         └─ changes/
            └─ 2021_to_2022/
               ├─ road_changes.gpkg
               ├─ road_width_segments.shp
               ├─ road_corridors.shp
               ├─ road_matches.shp
               ├─ canonical_roads.shp
               ├─ change_summary.json
               └─ evaluation_metrics.csv
```

`pipeline_result.json` 汇总输入模式、验证区、原始影像源、规范化分析源、有效观测范围、全部期次提取结果和变化结果，并记录局部宽度段、标准化走廊、匹配诊断和公共轴线成果路径；旧任务缺少这些字段时仍按已有中心线和宽度字段降级读取。界面的“打开最新成果”会直接打开对应任务目录。

## 可选人工编辑与成果评价

一键流程先自动完成“道路中心线 + SAM-MLoRA 道路面 + 概率引导融合 + 最终统一测宽 + 初次变化检测”。自动处理结束后，界面进入“人工编辑（可选）”：用户可以修正中心线并通过“应用编辑并更新相关结果”串行更新测宽、道路面、相邻变化对、评价、长时序成果和任务索引，也可以明确跳过，直接采用自动处理结果。

无需先运行新任务：使用菜单“项目 → 载入已有任务结果”，可直接选择旧任务的 `latest_pipeline.json` 或 `pipeline_result.json`。载入后即可查看已有正式结果、进入人工编辑和应用编辑；只有受编辑期次的后处理会增量执行，不会重新运行 SAMRoad 或 SAM-MLoRA。

结果页不再读取、缩放或展示 PNG 预览，以免大图阻塞界面；直接提供正式成果目录、长时序 SHP、属性表、任务报告和精度汇总入口。后端仍保留诊断图片供排障使用，不影响正式矢量成果 `road_centerlines.shp`、`road_surfaces.shp`、`roads.gpkg` 和 `road_changes.gpkg`。

人工编辑不是默认流程的闸门。自动处理完成后，在第三步选择项目/格网和期次并打开内置编辑工作台。编辑器把该期 `products/road_centerlines.shp` 作为一个全局最终网络打开，不再逐切片切换和重复修同一道路。背景是全部编辑影像构成的限尺寸全局概览，道路面、补画/擦除和手工测宽仍可使用。保存时生成权威的 `global_edited_centerlines.gpkg`，再自动投影回各源窗口；只有与几何、道路面或手工测宽影响范围相交的窗口会重新重建路面和测宽，其他窗口复用已有成果。随后程序统一拼接正式中心线、导出 SHP/GPKG，并自动重跑包含该期次的相邻变化对、评价和长时序道路表，不重新运行 SAMRoad 或 SAM-MLoRA。

变化检测先按中心线和局部宽度段判断道路存在性，再判断宽度变化。整段仅在后期存在时以该段完整标准化 Buffer 保留为新增，仅在前期存在时保留为灭失；双模型证据充分的对象标为自动确认，证据不足的对象保留到 `review_changes` 待复核层，不再静默删除。只有前后期均存在、匹配可靠并建立公共轴线时才判断拓宽/变窄；宽度缺失、C 级低质量、冲突或相对跳变超过默认 75% 只会排除宽度变化，不能取消有效观测区内的整段新增/灭失。逐项原因记录在 `qa_state`、`audit_reason`、`change_audit.csv` 和 `change_summary.json`。

对后处理仍无法得到宽度的道路，可在同一内置编辑工作台选择“手动测宽”，依次点击道路两侧边界。测线中点必须靠近目标中心线；保存后全局坐标测量会自动投影到对应窗口，覆盖目标连续道路链，并在“应用编辑并重新生成结果”时参与道路面重建、正式成果融合和相邻期变化重算。全局原始记录保存在 `runs/roads/centerline_edit/global_manual_widths.json`，投影后的窗口记录供现有测宽器使用。

人工编辑工作台会把正式 `road_surfaces.shp` 栅格化叠加到全局概览。手动测宽后会立即预览对应道路链路面；如果预览不正确，可撤销，或使用“擦除道路面”和“补画道路面”修正。全局增删掩膜保存为 `global_manual_surface_add.png` 和 `global_manual_surface_remove.png`，保存时自动投影为窗口掩膜，并在自动重建及宽度 Buffer 之后最后应用。

“查看长时序属性表”会在应用内直接读取 `05_长时序成果/road_life.shp`，显示全部非几何字段，并支持按 `road_id`、期次状态和事件码即时筛选；“打开长时序道路 SHP”仍可交给 QGIS/ArcGIS 查看空间几何。

点击“应用编辑并更新相关结果”后，人工编辑页会显示“编辑后增量重建”面板，实时显示当前阶段、进度和耗时；详细输出仍进入唯一的全流程日志。日志同时写入任务目录的 `_logs/人工编辑重建_<时间>.log`；可复制或直接打开。需要中止时点击“停止重建”，程序会停止完整子进程树，已有正式结果不会被主动删除，处理完日志中的原因后可再次应用编辑。

诊断目录中的融合对比图使用固定颜色区分来源：绿色为原始 SAMRoad 中心线，紫色为道路面骨架自动新增线，青色为自动断连补线，橙色为人工编辑中心线，蓝橙色为人工接受候选。结果页不自动加载这些图片，需要排障时可从成果目录查看。

启动编辑器前，GUI 会只读检查复核目录中的 `*_summary.json`、原始影像、prepared graph 和每期正式中心线 SHP；检查失败不会修改已有结果。编辑器通过 manifest 的 `review.directory`、`review.edited_directory`、`centerlines` 和期次 `result` 路径启动，原始 TIFF 不会被复制或覆盖。

### 自动融合规则（骨架全量加入 + 道路面约束短接）

一键流程会把道路面骨架化产生的每一条中心线全部加入最终成果，包括短线、孤立线、低置信线、块状区域分支和靠近双幅道路的骨架。评分、宽度、形状及拓扑匹配结果只作为审计字段保留，不再阻止任何道路面骨架入网；自动规则统一记录为 `all_surface_skeletons_as_is`。

加入时保留骨架本身的折线坐标，并分三层处理断缝。第一层连接“道路面骨架端点—已有 degree-1 悬挂端点”：默认距离不超过 96 像素、双端方向一致度不低于 0.85、A* 路径道路面覆盖率不低于 0.95、绕行比不超过 1.35。若道路面掩膜恰好在断缝处漏检，只在方向一致度不低于 0.95、道路概率均值不低于 0.50、下四分位数不低于 0.10、绕行比不超过 1.15 时使用概率证据补连。

第二层连接不同道路面区域中的骨架片段，只接受双方相互唯一且没有近距离竞争目标的延续端点。默认距离不超过 128 像素、方向一致度不低于 0.95、绕行比不超过 1.15；道路面连续覆盖率须不低于 0.70，或道路概率均值/下四分位数分别不低于 0.30/0.12。第三层只补原中心线中不同连通分量的 degree-1 端点断缝：距离不超过 96 像素、方向一致度和道路面覆盖率均不低于 0.95、绕行比不超过 1.15，并同样要求相互唯一、无竞争目标。

为避免斜穿空地、跨道路硬接等错误，每个端点最多参与一次连接，受保护双幅道路端点不参与；不允许自动接到任意道路边或路口内部，也不做全图无证据端点吸附。方向不一致、候选不唯一、缺少栅格证据或绕行过大时由程序自动跳过，不会建立待复核任务。

每条候选的审计结果仍写入 `runs/roads/width_review/<期次>_candidate_centerlines.csv`，安全补线另写入 `*_surface_skeleton_connectors.csv`，包含连接类型、起止候选、距离、路径长度、绕行比、双端方向一致度、道路面覆盖率、道路概率证据及得分。最终质量报告记录 `global_endpoint_snapping=false` 与实际的 `global_surface_gap_count`；融合预览中的紫色线表示道路面骨架及其道路面约束补线，绿色表示原始 SAMRoad 中心线。

上述规则只对重新生成的候选和最终图生效。旧 run 的 CSV、summary 和预览不会自动回填新分数或新接入类型；要使用新规则，必须重新运行任务（推荐从 GUI 的一键完整流程开始），不要只修改 manifest 或手工编辑旧 CSV。

全局融合完成后还会执行一次全自动跨组件残缝检查。程序自动拼接各瓦片的 `<期次>_centerline_probability.png`，保留低绝对值但相对周边连续的概率脊线；悬挂端点可以连接另一连通分量的相向端点，也可以沿概率脊线接入主路线内部。程序使用局部归一化中心线概率、道路面和方向约束运行 A*，将通过证据检查的曲线路径直接写入正式中心线；接到路线内部时会同步分割目标线，形成精确共享节点，不使用显示上重合、拓扑上分离的近似坐标。若中心线概率缺失但道路面连续覆盖率不低于 0.95，则仍可采用道路面证据补连；最大间隙为 192 像素。最终质量报告记录 `global_surface_gap_count`、`global_probability_gap_count`、`global_endpoint_gap_count`、`global_edge_attachment_count`、概率来源数和 `fully_automatic_accept_or_skip_without_pending_review` 决策策略。Windows 中文目录中的概率图和道路面图通过 Unicode 安全方式读取。

道路面骨架与现有网络的局部接触也会保留审计字段。仅当候选已经沿审计通过的道路面路径到达既有端点，或在道路面上精确接触既有边时，最终图才会复用节点或分割目标边；未审计的远程节点/边匹配不会被物化为连接。

## 启动

双击 `启动用户界面.bat`。启动器优先使用本项目内的 `env/samroad_env/python.exe`。

用户界面和人工编辑工作台会在创建窗口前启用 Windows 原生高 DPI 渲染，并按当前显示器的 100%/125%/150% 等缩放比例同步调整字体、窗口和侧栏尺寸，避免系统位图拉伸导致文字模糊。默认页面按 1280×820 的内容比例布局；屏幕空间不足时会自动限制到可用屏幕范围，高级参数拆分为多行以避免控件挤压重叠。

界面采用固定页头、横向流程指示、中部独立工作页和固定底部操作栏，不再把全部功能堆在一张滚动页面中。中部工作区在高级设置或日志展开后可用鼠标滚轮独立上下滑动，页头与底部主操作始终可见；宽屏下内容最大宽度受控并自动居中，避免输入框和卡片被过度拉长：

1. **数据准备**：新建或打开项目，连接并扫描外部原始数据目录；自动识别后只需确认候选映射，兼容配置和旧版格网入口默认折叠；
2. **自动处理**：一个“运行完整流程”入口自动完成运行前检查、新任务创建、未完成任务续跑和有效成果复用；局部重跑单独按依赖管理；
3. **人工编辑（可选）**：自动处理完成后，可直接进入专业编辑工作台修正中心线并自动更新相关结果，也可跳过；
4. **成果与评价**：用树形浏览器集中查看已完成与未生成成果，并自动匹配项目真值；任务载入和诊断位于全局菜单。

任务异常时详细日志会自动展开；正常情况下日志保持收起，不影响主要操作。

原有 `prepare`、`extract`、`change` 后端命令仍保留以便排障；用户界面默认呈现验证区一键完整流程，并把格网模式折叠为第二选项。
