# SAMRoad 长时序道路对象与属性表改造计划

## 1. 文档目的

当前“面向用户”项目能够对同一验证区的多期影像分别提取道路，并按自然时间顺序生成相邻两期的新增、消失、拓宽、变窄结果。对于 8 期影像，现有流程会得到 8 份单期道路成果和 7 份相邻期变化成果。

这种成果适合查看“某两期之间哪里变了”，但不适合直接回答以下长时序问题：

- 某一条道路在哪些年份存在；
- 它最早在哪一期出现、最后在哪一期仍然存在；
- 它在哪两个观测期之间新增或消失；
- 它经历过几次拓宽、变窄或位置调整；
- 某次变化是可靠变化，还是提取漏检、影像无数据或匹配不确定；
- 后续如何按道路对象进行生命周期统计，而不是重复读取 7 组两两变化 SHP。

本次改造的目标，是在保留现有单期提取和两期变化成果的同时，增加一套“道路对象—年度状态—变化事件”时序成果，使同一条道路在所有年份拥有稳定编号，并能通过 GIS 属性表和后续程序直接查询其生命周期。

> 本文是实施计划，不在本阶段修改现有推理和变化检测代码。

## 2. 现状判断

### 2.1 当前流程

当前主流程位于 `code/user_pipeline.py`，主要过程为：

1. 对每个期次分别生成 `road_centerlines.shp`、`road_surfaces.shp` 和 `roads.gpkg`；
2. 对自然排序后的相邻期次执行 `n-1` 次变化检测；
3. 每个年份对输出 `road_changes.shp`、`road_changes.gpkg`，以及按类型拆分的新增、消失、拓宽、变窄 SHP；
4. 人工修改某一期中心线后，只重跑与该期相邻的一个或两个变化对。

### 2.2 现有字段为什么不能直接承担长时序分析

单期中心线已有 `global_id`，但它是在每一期成果内部生成的编号，并不是跨年份不变的道路身份。两期变化成果已有 `change_id`，但该编号也只在一个年份对中有效，并且其几何是变化面片，不是稳定的道路对象。

因此不能通过以下方式可靠获得道路生命周期：

- 直接把 8 期中心线 SHP 合并后按 `global_id` 分组；
- 直接把 7 期 `road_changes.shp` 合并后按 `change_id` 分组；
- 只依据某个变化面片的空间位置，假定它始终代表同一整条道路。

需要新增一个跨期匹配与道路对象化步骤，为同一空间和拓扑含义的道路段分配稳定的 `road_id`。

## 3. 总体设计原则

### 3.1 分析对象采用“稳定道路段”，不采用整条道路面或整条街道

建议把道路对象定义为：**在稳定交叉口、道路端点和有效变化边界之间的一段中心线**。

原因如下：

- 一条很长的道路可能只有局部在某一年延伸或拓宽；
- 用整条道路作为一条记录，会把局部变化错误地传播到全路；
- 用过细的像素面片作为对象，又会使 ID 数量巨大且难以解释；
- 以路口—路口道路段为基本对象，既适合 GIS 查看，也适合网络和统计分析。

该对象在所有年份使用统一的稳定编号 `road_id`。宽度改变但走向和拓扑关系保持的，沿用同一 `road_id`；新增延伸部分生成新 `road_id`；明显改线的旧位置记录为消失、新位置记录为新增，并通过事件关系标注为疑似或确认改线。

### 3.2 不把“未提取到”直接等同于“道路消失”

每一期道路状态至少区分：

- `present`：确认存在；
- `absent`：确认不存在；
- `uncertain`：有影像但证据不足或匹配冲突；
- `no_data`：该位置在该期没有有效影像覆盖。

只有从 `present` 转为有足够证据支持的 `absent`，才生成正式 `removed` 事件。单期模型漏检、遮挡、云影、拼接空洞或拓扑断裂应进入 `uncertain`，不能直接写成道路灭失。

### 3.3 正式交付成果全部采用 Shapefile

用户最终拿到的长时序成果全部采用 SHP 矢量数据，不要求使用 GeoPackage、CSV 或外部数据库。每个 SHP 都配套输出同名 `.shx`、`.dbf`、`.prj`、`.cpg` 文件，统一使用 UTF-8 编码。

由于 Shapefile 不能在一个文件中保存多张关系表，本方案采用多份 SHP 共同表达道路生命周期：一份道路生命周期宽表、一份逐期状态长表、一份变化事件表，以及必要的谱系和复核表。所有表均带线或面几何，可以直接在 ArcGIS/QGIS 中打开和查询。

## 4. 建议的数据模型

正式成果建议为：

```text
05_长时序成果/
├─ road_life.shp         道路生命周期宽表，一条稳定道路段一行
├─ road_obs.shp          道路逐期状态长表，一条道路段×一个期次一行
├─ road_event.shp        道路变化事件线图层，一次事件一行
├─ event_parts.shp       新增、消失、拓宽、变窄的实际变化面片
├─ road_lineage.shp      分裂、合并、延伸、改线关系图层
└─ road_review.shp       不确定匹配和待人工复核道路段
```

其中 `road_life.shp` 是用户最常查看的主成果；`road_obs.shp` 是后续长时序分析的正式明细成果。二者均为 SHP，前者便于直接查看 8 期属性，后者便于追加更多年份和程序统计。

### 4.1 `road_life.shp`：稳定道路段生命周期主图层

| 字段         | 类型      | 含义                                               |
| ------------ | --------- | -------------------------------------------------- |
| `road_id`    | 文本      | 跨期稳定唯一编号，例如 `RD00000001`                |
| `grid_id`    | 文本      | 验证区或格网编号                                   |
| `from_node`  | 文本      | 起点稳定节点编号                                   |
| `to_node`    | 文本      | 终点稳定节点编号                                   |
| `first_obs`  | 文本/日期 | 第一次确认存在的观测期                             |
| `last_obs`   | 文本/日期 | 最后一次确认存在的观测期                           |
| `life_state` | 文本      | 当前生命周期状态：`active`、`removed`、`uncertain` |
| `present_n`  | 整数      | 确认存在的期次数                                   |
| `event_n`    | 整数      | 有效变化事件数                                     |
| `max_conf`   | 浮点      | 跨期最高置信度                                     |
| `min_conf`   | 浮点      | 跨期最低置信度                                     |
| `review_st`  | 文本      | 是否需要人工复核                                   |
| `geometry`   | 线        | 统一参考几何，不随单期轻微偏移变化                 |

`first_obs` 表示“第一次观测到”，不应解释为精确建成年份。例如 1980 年不存在、1985 年存在，只能判断其新增发生在 `(1980, 1985]` 区间。

### 4.2 `road_obs.shp`：逐期状态长表

这是后续长时序分析最重要的表。每个 `road_id` 在每个期次均有一行，即使该期不存在或无数据也保留记录。

| 字段         | 类型 | 含义                                        |
| ------------ | ---- | ------------------------------------------- |
| `road_id`    | 文本 | 关联 `road_life.shp` 的 `road_id`           |
| `period`     | 文本 | 年份或日期，例如 `2021`、`20210101`         |
| `status`     | 文本 | `present`、`absent`、`uncertain`、`no_data` |
| `width_m`    | 浮点 | 该期道路宽度；不存在时为空                  |
| `length_m`   | 浮点 | 该期匹配长度                                |
| `coverage`   | 浮点 | 参考道路段被该期道路支持的比例，0～1        |
| `match_sc`   | 浮点 | 跨期匹配综合分数，0～1                      |
| `extract_cf` | 浮点 | 单期提取置信度                              |
| `geom_dev_m` | 浮点 | 单期中心线相对参考几何的偏移量              |
| `source_fid` | 文本 | 对应单期中心线原始要素编号                  |
| `source_run` | 文本 | 来源任务/期次结果路径或标识                 |
| `qa_state`   | 文本 | `auto`、`reviewed`、`rejected`              |

对 8 期数据，一条道路段原则上有 8 行观测记录。该表可直接回答“某道路在哪些年份存在”，也便于后续程序进行时序统计。该 SHP 使用线几何；即使某期状态为 `absent`、`uncertain` 或 `no_data`，仍复制该 `road_id` 的参考线，并通过 `status` 字段表达状态，避免空几何兼容问题。

### 4.3 `road_event.shp` 与 `event_parts.shp`：变化事件成果

| 字段         | 类型 | 含义                                |
| ------------ | ---- | ----------------------------------- |
| `event_id`   | 文本 | 全项目稳定事件编号                  |
| `road_id`    | 文本 | 关联道路对象                        |
| `from_per`   | 文本 | 前一观测期                          |
| `to_per`     | 文本 | 后一观测期                          |
| `event_typ`  | 文本 | 见下方事件类型                      |
| `before_st`  | 文本 | 变化前状态                          |
| `after_st`   | 文本 | 变化后状态                          |
| `before_w`   | 浮点 | 变化前宽度                          |
| `after_w`    | 浮点 | 变化后宽度                          |
| `width_diff` | 浮点 | 宽度差                              |
| `event_cf`   | 浮点 | 事件置信度                          |
| `evidence`   | 文本 | 事件证据或规则                      |
| `qa_state`   | 文本 | 自动/已复核/驳回                    |
| `geometry`   | 线   | `road_event.shp` 中对应的稳定道路段 |

建议事件类型：

- `appeared`：第一次观测即存在，前面没有可判断的有效期次；
- `added`：前期确认不存在、后期确认存在；
- `removed`：前期确认存在、后期确认不存在；
- `widened`：同一道路宽度显著增加；
- `narrowed`：同一道路宽度显著减小；
- `rerouted`：道路拓扑功能延续但中心线位置发生明显改变；
- `unchanged`：状态和宽度均无显著变化，通常不必写入事件层；
- `uncertain_transition`：状态跨期变化但证据不足，只进入复核队列，不计入正式变化统计。

Shapefile 的单个图层不能混合线和面，因此拆成两份：

- `road_event.shp`：线图层，用稳定道路段表示事件对象，适合按 `road_id` 查询生命周期；
- `event_parts.shp`：面图层，保存新增、消失、拓宽、变窄的实际变化范围，并通过 `event_id` 和 `road_id` 关联到事件线。

现有 `road_changes.shp` 中的变化面片继续保留，并作为事件判定的重要空间证据。

### 4.4 `road_lineage.shp`：复杂对象关系图层

道路网络跨期匹配会遇到一对多和多对一关系，不能强行只做一对一匹配。建议记录：

| 字段         | 含义                                            |
| ------------ | ----------------------------------------------- |
| `parent_id`  | 前一对象 ID                                     |
| `child_id`   | 后一对象 ID                                     |
| `period`     | 关系发生期次                                    |
| `relation`   | `split`、`merge`、`extension`、`reroute`        |
| `confidence` | 关系置信度                                      |
| `qa_state`   | 复核状态                                        |
| `geometry`   | 父子道路段代表点之间的关系线，便于在 GIS 中定位 |

典型规则：道路局部延长时，原有共同部分尽量保持原 `road_id`，新增延伸部分使用新 `road_id`，并以 `extension` 建立关系；路口新增导致旧道路段被切分时，用 `split` 记录其谱系，而不是悄悄更换全部编号。

### 4.5 `road_life.shp`：用户属性表宽表字段

对 8 个期次，在生命周期主字段基础上追加每期短字段。考虑 Shapefile 字段名长度限制，字段建议使用：

| 字段示例 | 含义                                                                     |
| -------- | ------------------------------------------------------------------------ |
| `S2021`  | 2021 状态码：`P`存在、`A`不存在、`U`不确定、`N`无数据                    |
| `W2021`  | 2021 宽度，单位米                                                        |
| `C2021`  | 2021 置信度                                                              |
| `E2122`  | 2021→2022 事件码：`A`新增、`R`消失、`W`拓宽、`N`变窄、`U`不确定、`0`未变 |

示例属性记录：

| road_id    | S2018 | S2019 | S2020 | S2021 | S2022 | E1920 | E2122 | first_obs | last_obs |
| ---------- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | --------- | -------- |
| RD00001234 | A     | A     | P     | P     | P     | A     | W     | 2020      | 2022     |

这表示该道路在 2018、2019 年确认不存在，2020 年新增，2021 年仍存在，2021→2022 年发生拓宽。宽表主要用于目视查询和制图；严谨统计应读取同样为 SHP 的 `road_obs.shp` 和 `road_event.shp`。

## 5. 跨期道路 ID 构建方法

### 5.1 输入统一

每个验证区/格网内：

1. 读取所有期次正式的 `road_centerlines.shp`、`road_surfaces.shp`；
2. 读取所有相邻期次 `road_changes.shp`；
3. 统一到当前管线已建立的公共分析 CRS 和米制网格；
4. 清理空几何、重复线、极短毛刺和无效拓扑；
5. 保留单期 `global_id`、宽度、质量等级、融合来源和人工复核状态作为来源字段。

### 5.2 建立参考道路网络

不建议简单叠加 8 期中心线后直接切割，因为不同年份的轻微位置误差会产生大量平行碎线。建议采用“参考期骨架 + 逐期汇入”的方式：

1. 选择质量最好或最新且人工复核充分的一期作为初始参考网络；
2. 在位置容差内，把其他期次中心线吸附/匹配到已有参考道路段；
3. 对明显未匹配、且有道路面证据支持的线路加入参考网络；
4. 在稳定路口、端点、有效新增/消失边界处切分，形成原子道路段；
5. 对原子段进行规范排序并生成永久 `road_id`；
6. `road_id` 一经正式发布，不因后续重新运行或追加年份而整体重编号。

首版可以允许用户指定参考期；后续再增加自动参考期评分。ID 生成建议使用项目内持久化序列，而不是根据几何哈希直接生成，以免轻微编辑导致 ID 全部变化。

### 5.3 每期对象匹配与状态赋值

每个参考道路段与每期中心线/道路面进行空间匹配，综合使用：

- 中心线缓冲范围内的双向重叠比例；
- 平均距离和最大距离；
- 方向夹角；
- 起终节点邻接关系是否一致；
- 道路面覆盖率；
- 宽度差；
- 现有相邻期变化面片是否支持新增、消失或宽度变化；
- 前后相邻年份的状态连续性。

匹配不能只依赖最近距离。建议先生成候选，再用加权分数或分层规则确定：

- 高分且唯一：自动匹配；
- 多个分数接近：标记 `uncertain` 并进入复核；
- 无匹配但影像和道路面证据明确：判定 `absent`；
- 影像无有效覆盖：判定 `no_data`。

首版阈值可以沿用现有变化检测的米制位置容差，并另行增加道路段重叠率、方向和拓扑阈值；正式阈值需在代表性验证区标定。

### 5.4 事件推导

完成所有 `road_obs.shp` 逐期状态后，再根据相邻期状态生成事件，不应反过来只靠 7 份变化面拼接生命周期。

基本状态转换如下：

| 前期              | 后期                             | 事件                                       |
| ----------------- | -------------------------------- | ------------------------------------------ |
| absent            | present                          | added                                      |
| present           | absent                           | removed                                    |
| present           | present，宽度显著增加            | widened                                    |
| present           | present，宽度显著减小            | narrowed                                   |
| present           | present，走向/位置和谱系显著改变 | rerouted                                   |
| uncertain/no_data | 任意                             | uncertain_transition，不直接统计为正式变化 |

现有变化检测结果用于校验和定位事件范围：只有对象状态转换、单期证据和成对变化证据相互支持时，事件置信度才设为高。

### 5.5 时序一致性修正

对 `present → absent → present` 这类单期跳变进行专项检查：

- 若前后两期几何连续且中间期影像质量较差，优先标记中间期为 `uncertain`，避免虚假的“消失后重建”；
- 若中间期有清晰影像证据确认不存在，则允许形成 `removed` 和后续 `added` 两个事件；
- 自动修正必须保留原始判定、修正规则和置信度，便于审计。

## 6. 与现有项目的集成方案

### 6.1 新增后处理模块

建议新增：

```text
code/temporal_road_analysis.py
```

主要职责：

1. 从 `pipeline_result.json` 收集各期道路和各相邻变化对；
2. 构建或更新稳定参考道路网络；
3. 写入逐期观测、事件和谱系字段；
4. 导出生命周期、逐期状态、事件、变化面片、谱系和复核 SHP；
5. 生成 SHP 形式的长时序待复核清单。

建议拆分为可测试函数：

- `load_temporal_inputs()`；
- `build_reference_segments()`；
- `match_period_observations()`；
- `resolve_lineage()`；
- `derive_events()`；
- `apply_temporal_consistency()`；
- `write_temporal_outputs()`。

### 6.2 主流程调用位置

在 `user_pipeline.py` 完成全部单期提取和相邻变化检测后，增加“长时序汇总”阶段：

```text
多期道路提取
    → 相邻期变化检测
    → 长时序道路对象化与事件汇总
    → 任务报告/成果索引
```

`pipeline_result.json` 增加：

```json
{
  "temporal_result": {
    "life_shp": ".../05_长时序成果/road_life.shp",
    "observations_shp": ".../05_长时序成果/road_obs.shp",
    "events_shp": ".../05_长时序成果/road_event.shp",
    "event_parts_shp": ".../05_长时序成果/event_parts.shp",
    "lineage_shp": ".../05_长时序成果/road_lineage.shp",
    "review_shp": ".../05_长时序成果/road_review.shp"
  }
}
```

### 6.3 人工编辑后的增量更新

当前人工编辑一期道路后，会重跑它相邻的变化对。加入长时序模块后还应：

1. 重新匹配被编辑期的 `road_obs.shp` 记录；
2. 重算该期前后两个时间间隔的 `road_event.shp` 记录；
3. 检查编辑是否造成道路段分裂、合并或参考网络变化；
4. 尽量保留未受影响的 `road_id`；
5. 若必须调整 ID，写入 `road_lineage` 和 ID 变更审计表；
6. 重新导出宽表，但不重跑无关期次的模型推理。

### 6.4 用户界面建议

在“查看结果”中增加“长时序道路”成果组：

- 打开道路生命周期 `road_life.shp`；
- 打开逐期状态和事件 SHP；
- 按 `road_id` 查看生命周期；
- 按年份筛选新增/消失/拓宽/变窄；
- 打开时序待复核清单；
- 显示汇总指标：道路对象数、各期存在数、各时间段事件数、不确定对象数。

首版无需制作复杂时间轴编辑器，先保证成果结构正确并可在 QGIS/ArcGIS 中查询。

## 7. 实施阶段

### 阶段 A：字段规范和最小可用版本

目标：先跑通 8 期数据，得到可查询的稳定道路段与逐期状态。

工作内容：

1. 确认 8 期实际年份、统一 CRS 和单期中心线字段；
2. 实现参考道路段生成与持久 `road_id`；
3. 实现逐期空间匹配，输出 `present/absent/uncertain/no_data`；
4. 输出 `road_life.shp`、`road_obs.shp` 和 `road_review.shp`；
5. 暂以一对一高置信匹配为自动结果，复杂关系全部进入复核队列。

验收重点：任取一条道路，能从属性表准确读取 8 期状态，且重复运行后 `road_id` 不发生无理由变化。

### 阶段 B：事件融合和时序一致性

目标：把现有两两变化面关联到稳定道路对象。

工作内容：

1. 生成全局唯一 `event_id`；
2. 关联 `added/removed/widened/narrowed` 变化面与 `road_id`；
3. 计算事件置信度；
4. 增加单期跳变检查；
5. 输出 `road_event.shp` 和 `event_parts.shp`。

验收重点：属性表状态转换与现有相邻变化结果方向一致；不确定状态不会被错误统计为新增或消失。

### 阶段 C：分裂、合并、延伸和改线谱系

目标：处理真实道路网络中不能用一对一匹配描述的复杂演化。

工作内容：

1. 实现一对多、多对一候选识别；
2. 建立 `road_lineage`；
3. 区分局部延伸、路口新增导致的切分和整体改线；
4. 提供人工确认入口；
5. 确保确认后 ID 与谱系可持久保存。

### 阶段 D：GUI 和增量追加年份

目标：让用户可以追加第 9 期、第 10 期，而不用重建全部历史身份。

工作内容：

1. GUI 增加长时序成果入口和筛选；
2. 新增年份时只匹配新期，并重算最后一个相邻时间段；
3. 新增道路获得新 ID，既有道路尽量继承 ID；
4. 提供版本、参数和 ID 变更审计；
5. 增加跨项目/多格网汇总能力。

## 8. 测试与验收方案

### 8.1 必测合成场景

至少构造以下可控用例：

1. 8 期始终存在且宽度不变；
2. 第 3 期新增并持续存在；
3. 第 6 期消失且后续不再出现；
4. 第 4 期拓宽、第 7 期变窄；
5. 中间一期漏检，但前后期连续存在；
6. 某一期无有效影像覆盖；
7. 道路局部延长；
8. 道路被新路口切分；
9. 两条道路合并或一条道路分叉；
10. 道路明显改线；
11. 相邻平行道路，防止错误串号；
12. 人工编辑中间期后，仅相关观测和事件更新。

### 8.2 核心验收指标

- **身份保持率**：真实同一道路跨期保持同一 `road_id` 的比例；
- **错误串号率**：不同道路被错误赋为同一 `road_id` 的比例；
- **状态准确率**：`present/absent/uncertain/no_data` 分类准确率；
- **事件准确率**：新增、消失、拓宽、变窄的目标级 Precision/Recall/F1；
- **ID 稳定性**：相同输入和参数重复运行，未受影响对象 ID 完全一致；
- **增量稳定性**：追加新年份后，历史未变化对象 ID 不变；
- **可追溯性**：任一状态或事件均可追溯到来源期次要素、变化面和运行版本。

### 8.3 属性表验收示例

在 QGIS/ArcGIS 中选择 `road_id = 'RD00001234'` 后，应能够：

1. 在 `road_life.shp` 一行内看到 8 期状态码、宽度和相邻变化码；
2. 在 `road_obs.shp` 中看到该 ID 的 8 行观测记录；
3. 在 `road_event.shp` 中看到该 ID 的全部有效变化事件；
4. 从 `source_fid/source_run` 定位回原始单期成果；
5. 区分“确认不存在”和“无法判断”。

## 9. 风险与控制措施

### 9.1 单期几何抖动造成伪变化

控制：使用公共网格、参考中心线匹配、双向重叠、方向和拓扑联合约束；宽度和位置变化必须超过阈值并有道路面证据。

### 9.2 道路网络切分不一致造成 ID 爆炸

控制：只在稳定节点和有效变化边界切分；合并距离过近的伪节点；通过谱系表表达真实分裂，而不是每期重新编号。

### 9.3 Shapefile 字段和编码限制

控制：正式成果全部使用 SHP；所有字段名限制在 10 个字符以内；使用短字段编码，并为每个 SHP 写出 `.shx`、`.dbf`、`.prj`、`.cpg`，统一使用 UTF-8。

### 9.4 8 期以后宽表不断膨胀

控制：所有算法和统计以 `road_obs.shp` 长表为准；`road_life.shp` 宽表同步输出。追加较多年份后，如字段数接近 Shapefile 上限，则按时间段额外输出分段宽表，但 `road_id` 保持一致。

### 9.5 自动把漏检解释为道路消失

控制：设置 `uncertain/no_data` 状态，增加前后期连续性检查；高风险事件进入复核清单，未经确认不进入正式变化统计。

## 10. 建议的首版范围与交付物

首版建议不要一次完成全部复杂谱系和 GUI 时间轴，而是优先交付以下闭环：

1. 读取现有 `pipeline_result.json` 中的 8 期道路和 7 期相邻变化结果；
2. 生成稳定的路口—路口道路段 `road_id`；
3. 为每个 `road_id` 生成 8 期 `road_obs.shp` 记录；
4. 生成新增、消失、拓宽、变窄 `road_event.shp` 和 `event_parts.shp`；
5. 输出 `road_life.shp`、`road_obs.shp`、`road_event.shp`、`event_parts.shp`、`road_lineage.shp`；
6. 输出 `road_review.shp`，承接不确定匹配；
7. 增加自动化测试，验证 ID 稳定性、状态转换和人工编辑后的局部更新。

完成首版后，用户即可通过一个属性表查看某条道路在哪些年份存在、何时消失、何时发生宽度变化；后续分析也可以直接读取规范化长表，而不再自行拼接多组两两变化 SHP。

## 11. 实施前需要最终确认的业务规则

编码前建议与业务方确认以下规则，并写入项目配置：

1. 8 个期次的准确名称是年份、日期还是影像批次；
2. “某条道路”的业务粒度是否接受“稳定路口—路口道路段”；
3. 已确定采用自动保守口径：绝对值 2 米且相对值 20%，并叠加互为最佳匹配、重合率、持续长度、质量等级和最小变化面积约束；
4. 道路暂时被遮挡或提取失败时，是否统一记为 `uncertain`；
5. 道路改线是按“旧路消失 + 新路新增”，还是需要额外 `rerouted` 类别————回答：按旧路消失 + 新路新增
6. 是否需要用户手工锁定/合并/拆分 `road_id`；————不要有手工步骤
7. 所有 SHP 是否统一采用项目分析 CRS，并配套输出完整附件；
8. 后续是否需要追加年份并保持历史 `road_id` 不变。

若暂时无法确认，首版默认采用本文建议：路口—路口道路段、四状态观测、改线同时保留新增/消失证据并建立谱系，所有正式交付成果均为 SHP 矢量数据。
