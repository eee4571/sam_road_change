# 814 修改说明

## 2026-08-18 Tkinter 业务流程重构

- 四步流程统一为“数据准备 → 自动处理 → 人工编辑（可选）→ 成果与评价”。
- 项目目录与外部原始数据源分离；项目内固定使用原子写入的 `project_config.json` 保存路径、映射、候选项和当前活动任务，原始 SHP、TXT 与影像不移动、不复制、不重命名。
- 数据页合并为“连接数据源、扫描数据、添加/修改/移除映射、检查数据”；映射变化自动保存，兼容配置导入/导出收进高级设置。
- “运行完整流程”自动创建任务或继续当前活动任务。道路输入/模型参数变化按期次失效，变化阈值变化只失效变化检测和下游成果，取消后再次运行自动续跑。
- 局部重跑明确区分“只重跑所选期次”和“重跑并更新相关结果”；后者按道路提取、相邻变化对、评价、长时序成果、报告和索引的顺序串行执行。
- 人工编辑主流程只保留“打开编辑工作台”和“应用编辑并更新相关结果”；外部编辑成果导入移入高级操作，应用编辑不会重跑 SAMRoad 或 SAM-MLoRA。
- 成果页改为树形浏览器，未生成成果明确显示状态；项目真值自动匹配，缺少时补充并自动保存；旧任务索引继续可从“项目”菜单载入。

本次只修改当前 Tkinter 工作流及其后端，未查看或改动 `新UI框架`。

## 输入可靠性与速度

- 主流程、SAMRoad 和 SAM-MLoRA 统一使用 `input_catalog.py` 读取 TXT。
- 支持 UTF-8、UTF-16 LE/BE、GB18030、GBK、Windows ANSI；错误定位到 TXT、检测编码、行号和影像路径。
- 模型启动前检查所有期次中每张影像能否打开、CRS、波段和数据类型，避免推理中途才遇到坏影像。
- 取消为计算覆盖范围而预先扫描整幅影像有效像元；按真实验证区几何生成窗口，每个窗口只读取空间相交的影像。
- L 型、多部件和带洞验证区按真实 Polygon/MultiPolygon 掩膜处理，外包矩形空角不生成任务。
- 少量未覆盖像元写为 NoData 并继续；整期完全没有有效数据才停止。
- 规范化结果按输入指纹和窗口保存状态，中断后复用已完成窗口。

## 期次顺序

- 支持 `YYYY`、`YYYYMM`、`YYYYMMDD`、`YYYY-MM-DD`，例如 `20260321.txt`。
- GUI 启动任务前展示并确认固化后的期次顺序和所有相邻变化对。
- 提取、变化检测、评价和长时序成果共用同一顺序，不依赖文件扫描顺序。

## 变化检测

- 先判道路存在性，再判宽度变化。
- 整段新增/灭失不会被宽度缺失、低质量或异常宽度差取消。
- 双模型证据不足的新增/灭失保留在 `review_changes` 层，并写明 `qa_state`、`audit_reason`。
- 前后均存在道路的相对宽度跳变超过默认 75% 时，只排除拓宽/变窄。
- `change_audit.csv` 和 `change_summary.json` 记录规则命中、复核和排除数量。

## 中心线采样与路口模式

- 道路面骨架候选默认采样步长由 10 px 调整为 16 px，与普通 SAMRoad 道路线密度一致。
- 默认 `sparse` 路口模式移除学习路口核心附近的冗余普通节点，降低假路口和乱连风险。
- GUI 高级参数可切换为 `dense_legacy`，恢复旧版密集路口节点方式。

## 全局最终中心线编辑

- 编辑器现在把每期 `products/road_centerlines.shp` 作为一个全局最终网络打开，不再逐切片重复编辑。
- 保存权威文件 `runs/roads/centerline_edit/global_edited_centerlines.gpkg`。
- 手工测宽、道路面补画/擦除在全局概览中操作，并自动投影回对应源窗口。
- 保存时计算影响范围；未受影响切片复用原成果，只在受影响窗口内重建道路面和道路链宽度。
- 应用后统一拼接和导出最终 SHP/GPKG，并重跑该期相邻变化对、评价和长时序成果；不会重跑 SAMRoad 或 SAM-MLoRA。
