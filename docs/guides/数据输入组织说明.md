# SAMRoad 数据输入组织说明

本文面向直接使用软件的业务人员，说明当前版本支持的数据组织方式、命名规则和提交前检查方法。建议先按本文整理数据，再双击 `启动用户界面.bat`。

## 1. 首选组织方式：多验证区、多时相项目

适用于一个或多个业务验证区的多期道路提取、相邻期次变化检测和总精度评价。这是用户界面的默认模式。

建议为每个项目单独建立一个文件夹，原始数据和输出目录分开：

```text
某市道路变化项目/
├─ area_north/
│  ├─ 01_验证区/
│  │  └─ boundary.shp（及同名 .shx/.dbf/.prj）
│  ├─ 02_影像/
│  │  ├─ 2021.txt
│  │  ├─ 2022.txt
│  │  └─ 2024.txt
│  └─ 03_变化真值/
│     ├─ 2021_to_2022.shp（及同名附件）
│     └─ 2022_to_2024.shp（及同名附件）
├─ area_south/
│  ├─ 01_验证区/
│  │  └─ boundary.shp
│  ├─ 02_影像/
│  │  ├─ 2020.txt
│  │  ├─ 2023.txt
│  │  └─ 2025.txt
│  └─ 03_变化真值/
│     ├─ 2020_to_2023.shp
│     └─ 2023_to_2025.shp
├─ 04_成果输出/（仅当前正式业务成果和 result_index.json）
├─ _work/（任务状态、续跑工作区、缓存；无需人工浏览）
└─ _logs/
```

在用户界面中对应填写：

1. 在“① 数据准备”中新建或打开项目，再点击“连接数据源”选择 `某市道路变化项目`；项目目录与外部原始数据目录可以相互独立；
2. 程序把项目根目录下每个验证区文件夹作为独立任务；其 `01_验证区` 必须且只能有一个边界 SHP；
3. 每个验证区独立读取自己的 `02_影像` 和 `03_变化真值`，所以不同验证区可以具有不同的影像、年份组合和真值；
4. 进入“② 自动处理”完成道路提取和相邻期次变化检测；如需修改成果目录，展开“输出位置与高级设置”；
5. 如需总精度评价，完成处理后进入“④ 成果与评价”，点击“评价全部结果”；也可只选择一个变化对单独评价；
6. 点击“运行完整流程”即可；任务会在内部先校验数据、模型、CPU/CUDA 环境、参数、输出目录和磁盘空间。“检查数据”只检查验证区、TXT、影像元数据、覆盖、期次和真值映射。

程序在每个验证区内部只比较自然排序后相邻的期次。例如 north 执行 `2021 → 2022`、`2022 → 2024`，south 执行 `2020 → 2023`、`2023 → 2025`；不同验证区之间不会互相配对。

### 1.1 验证区要求

- 必须是非空的 `Polygon` 或 `MultiPolygon` 面数据，并且必须声明 CRS；
- 必须使用 Shapefile；`.shp`、`.shx`、`.dbf`、`.prj` 等同名文件必须放在一起，不能只复制 `.shp`；
- 验证区应是实际需要分析的范围，不要用远大于业务区的省级或全国外包矩形；
- 验证区可为 L 型、多部件或带洞 Polygon/MultiPolygon；程序按真实几何生成窗口，不会处理外包矩形的空白角落；
- 影像应覆盖主要业务范围。极少量标注越界或局部未覆盖会写为 NoData 并继续，整期在验证区内没有任何有效数据时才停止。

### 1.2 影像要求

- 每个项目至少需要两个期次；
- 每个期次必须选择一个 TXT 影像路径清单；不能直接选择影像文件或影像目录；
- 当前可识别 `.tif`、`.tiff`、`.img`、`.jp2`、`.vrt`、`.png`、`.jpg`、`.jpeg`、`.bmp`；生产任务强烈推荐带 CRS 和仿射变换的 GeoTIFF；
- TXT 中只应列出本期原始影像，不要混入掩膜、缩略图、预览图或其他非输入图片；
- 同一期的全部影像必须具有相同的波段数和数据类型；
- 所有影像必须声明 CRS。不同 CRS 可以由程序统一，但推荐各期使用一致的投影坐标系、分辨率、波段顺序和数据类型；
- 程序以第一期第一张影像的 CRS 作为分析 CRS，并按全部输入中的最高空间分辨率建立公共网格。误放一张分辨率异常高的影像会显著增加内存、磁盘和耗时；
- 如果影像存在无效边缘或空洞，应在栅格元数据或有效像元掩膜中正确声明 NoData。未声明 NoData 时，程序不会擅自把像元值 `0` 当作无效；
- 原始影像不会被覆盖，但任务目录会产生规范化影像、中间结果和预览图。大任务建议把输入和输出放在本地 SSD，并预留充足空间。

### 1.3 TXT 影像清单

影像数量很多、分布在多个目录或网络盘时，可为每个期次建立一个 TXT。每行一张影像，空行和以 `#` 开头的注释行会被忽略。

```text
# 2021 年影像
D:\遥感影像\2021\tile_001.tif
D:\遥感影像\2021\tile_002.tif
\\server\share\2021\tile_003.tif
```

也可使用相对于 TXT 文件所在目录的相对路径：

```text
tiles\tile_001.tif
tiles\tile_002.tif
```

TXT 由所有模块共用同一个解码器，支持 UTF-8/UTF-8 BOM、UTF-16 LE/BE、GB18030、GBK、Windows 当前 ANSI 代码页，并兼容常见西文代码页。路径包含空格时可以直接填写，也可以用英文单引号或双引号包围。程序会在模型启动前逐行检查，报错给出 TXT、行号、检测编码和实际路径，不再静默跳过坏路径。对大批量任务，网络盘会明显影响读取速度，条件允许时建议先复制到本地 SSD。

### 1.4 变化真值要求

精度评价在结果阶段按变化对独立运行。三个期次最多可评价两个相邻变化对，四个期次最多可评价三个；没有真值也不影响道路和变化成果生成，只是不生成对应的 `evaluation_metrics.csv`。

每个验证区的两两年份变化真值 SHP 使用 `BHBM` 字段区分类型：`BHBM=2` 为新增，`BHBM=3` 为变化，`BHBM=4` 为灭失。评价时不区分拓宽和变窄，两者统一归入“变化”。可以逐对评价，也可以跨所有验证区和相邻期次生成总精度。两个主指标均按变化区域面积计算：

- 全部变化区域查全率：任意预测变化覆盖的真值变化面积 / 全部真值变化面积；
- 新增/变化/灭失判断正确率：已被检出的真值变化面积中，类型判断正确的面积占比。
- 变化区域中心线平均偏移：仅统计已经空间匹配的新增和灭失对象；同一真值道路面对应双线预测时，先合并为一个道路走廊再提取代表中心轴，然后计算双向骨架距离并按轴长汇总。漏检由查全率反映，不混入位置偏移；`BHBM=3` 宽度变化面不唯一确定道路轴线，因此不参与该指标。

- 真值必须是可读取的线或面 Shapefile，并且必须声明 CRS；
- `.shp`、`.shx`、`.dbf`、`.prj` 等同名附件必须齐全；
- 真值文件名建议固定为 `<前期>_to_<后期>.shp`；
- 若只评价“是否发生变化”，真值可以不含类型字段；
- 若要分别评价变化类别，可增加 `change_type` 字段，并在界面的“真值类型字段”中填写该字段名；
- 支持的常用类型值包括：`added/新增`、`removed/灭失`、`widened/拓宽`、`narrowed/变窄`；
- 真值范围应落在验证区内，线真值会按评价容差缓冲后参与面积和目标级指标计算。

如果业务任务没有变化真值，直接运行生产流程即可；不必为满足输入要求而制作空真值。

## 2. 大批量组织方式：多格网目录

适用于许多独立格网或行政区批量运行，并且不要求逐对加载变化真值的场景。在界面中展开“备用选项：格网目录模式”。

推荐结构如下：

```text
批量格网数据/
├─ area_001/
│  ├─ 2021/
│  │  ├─ tile_001.tif
│  │  └─ tile_002.tif
│  ├─ 2022/
│  │  ├─ tile_001.tif
│  │  └─ tile_002.tif
│  └─ 2024/
│     └─ tile_001.tif
├─ area_002/
│  ├─ 2021/
│  │  └─ tile_001.tif
│  └─ 2022/
│     └─ tile_001.tif
└─ province_shp/
   └─ ...
```

也支持每个格网直接放置期次 TXT：

```text
批量格网数据/
├─ area_001/
│  ├─ 2021.txt
│  ├─ 2022.txt
│  └─ 2024.txt
└─ area_002/
   ├─ 2021.txt
   └─ 2022.txt
```

还可以直接使用 `area_001/2021.tif`、`area_001/2022.tif` 的简化形式。一个格网内建议只采用一种形式；如果同一期同时存在 TXT、同名影像和同名目录，程序优先使用 TXT。

批量格网模式规则：

- 根目录的每个一级子目录视为一个格网；
- 每个格网至少需要两个有效期次，否则整个任务会在扫描阶段拒绝运行；
- 每个格网只与自身的相邻期次比较，不会跨格网匹配；
- `province_shp`、`shp`、`vector`、`vectors` 等辅助矢量目录会被忽略；
- 当前格网模式不使用统一验证区，也不加载相邻期次真值，因此不会生成真值评价指标。

## 3. 命名和路径建议

- 期次支持 `YYYY`、`YYYYMM`、`YYYYMMDD` 和 `YYYY-MM-DD`，例如 `20260321.txt`；程序执行真实日历校验并在运行前展示固化后的顺序及相邻变化对；
- 格网名使用稳定编号，如 `area_001`、`area_002`，不要在同一批次中途改名；
- 文件名只表达期次、格网和切片编号，不要把很长的项目说明塞进文件名；
- 中文路径受支持，但部分底层 GIS 组件仍受 Windows 传统路径长度限制。建议把项目放在较短路径，如 `D:\SAMRoadTasks\项目A`；
- 不要把成果输出目录建在原始影像目录内部；TXT 只填写明确的原始影像路径；
- 同一任务名称不能重复。若不填写任务名称，程序自动生成带时间的名称；
- 不要直接修改 `outputs` 中的中间目录名和 JSON 索引路径。如需归档，应整体移动完整任务目录。

## 4. 大影像和磁盘空间建议

当前版本会先把验证区内各期影像统一到公共分析网格，再切成推理切片。规范化已经采用 4096 像素窗口流式处理，内存不再随整幅验证区等比例增长；但验证区很大或输入分辨率很高时，中间影像数量、磁盘占用和总耗时仍会明显增加。

可先估算单期未压缩像元量：

```text
宽度像元数 × 高度像元数 × 波段数 × 每像元字节数
```

例如，`40000 × 40000`、3 波段、8 位影像的单期未压缩像元数据约为 4.8 GB。流式处理只保留当前窗口的镶嵌和掩膜，但磁盘仍需容纳所有规范化切片及下游成果。建议：

- 超大区域按互不遗漏、少量重叠的业务分区拆成多个项目或格网；
- 各期使用相近分辨率，先排除异常高分辨率影像；
- 输出盘可用空间至少按原始数据总量的 3～5 倍预留，正式投产前用代表性小区域实测一次；
- 任务运行期间不要移动输入文件、断开网络盘或休眠电脑；
- 每批先用少量格网试运行，确认 CRS、NoData、成果位置和变化阈值后再扩大批次。

## 5. 提交前检查表

开始运行前逐项确认：

- [ ] 验证区是 `.shp` 面数据、非空并带 CRS；
- [ ] 至少有两个期次，期次名称无重复且排序符合业务时间；
- [ ] 每一期都选择了 `.txt`，其中所列影像均能打开并带 CRS；主要业务范围有覆盖，已知的少量越界可接受为 NoData；
- [ ] 同一期影像波段数和数据类型一致；
- [ ] 影像 TXT 没有列入掩膜、预览图或其他非输入图片；
- [ ] NoData 定义正确，没有把有效的黑色像元误标为无效；
- [ ] 如需评价，已为待评价的相邻期次对准备真值 `.shp`，并计划在结果页运行；
- [ ] 真值和验证区的 Shapefile 同名附件齐全；
- [ ] 输入路径可访问，输出目录可写，磁盘空间充足；
- [ ] 项目路径尽量短，任务名称未与已有输出重复；
- [ ] 正式大批量运行前已完成小范围试运行。

### 运行中断后的继续方法

1. 保持项目配置中的当前活动任务不变；
2. 再次点击“运行完整流程”；
3. 程序自动读取 `job_state.json`，复用输入和参数未变化且成果完整的阶段，并继续未完成阶段；
4. 修改某一期输入时，只失效该期道路成果及前后相邻变化对；修改变化阈值时只失效变化检测及其下游成果；
5. 如需保留旧任务并从头开始，可在高级设置中指定新的手工任务名称。

任务状态保存在项目 `_work/tasks` 下对应任务的 `job_state.json`，用于完整流程续跑、局部重跑、编辑后更新和历史任务恢复；不要手工修改 `_work`。面向用户的汇总报告位于 `04_成果输出/task_report.csv` 和 `task_report.json`，正式成果清单为 `result_index.json`。

正式成果按固定业务位置更新：单期重跑覆盖 `<区域>/01_单期道路/<期次>`，变化对重跑覆盖 `<区域>/02_变化检测/<前期>_to_<后期>`；更新相关结果时还会重新发布受影响的长时序和精度评价。任务名称不会出现在正式成果路径中。

## 6. 常见错误与处理

| 提示 | 常见原因 | 处理方法 |
| --- | --- | --- |
| 找不到期次影像输入 | 路径填错、TXT 路径失效、网络盘未连接 | 逐行检查路径，在资源管理器中确认可打开 |
| 影像缺少 CRS | 普通 PNG/JPG 或 GeoTIFF 未写空间参考 | 在 GIS 软件中正确赋予/导出带 CRS 的 GeoTIFF |
| 整个期次没有有效数据 | TXT 影像与验证区完全不相交、网络盘数据不可读或 NoData 定义错误 | 检查诊断中的期次、TXT 行号和路径；修正影像或验证区。局部小缺口不会触发此错误 |
| 同一期波段数或数据类型不一致 | 混入不同产品、缩略图或掩膜 | 清理期次目录，并统一波段和数据类型 |
| 精度评价缺少真值 | 尚未选择待评价变化对的真值 | 在结果页选择变化对和对应真值 SHP |
| 格网少于两个期次 | 某个一级子目录只含一期有效影像 | 补齐期次，或把该目录移出本批次 |
| 任务目录已存在 | 手工填写的任务名称与历史任务重复 | 换一个任务名称，或留空让程序自动生成 |
| 运行很慢或内存不足 | 验证区过大、分辨率异常高、从网络盘读取 | 拆分项目、统一分辨率、改用本地 SSD |
