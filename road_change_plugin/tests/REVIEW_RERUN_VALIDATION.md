仅测试 PlugTest 副本 `project/plug_rv` 的区域 1、变化对 **20221020 → 20230222**。两轮桌面确认均为 0 个道路期次、1 个变化对。原项目不写入。

1. 在 1015 桌面界面选择该变化对并重跑，完成变化检测、长时序、评价和发布。
2. 按用户指定的测试规则准备复核草稿：含真值辅助区间的对象全部保留，其余全部剔除。来源通过同类型审计区间与对象的正面积相交判断，仅边界接触不算。混合来源归为含真值辅助。
3. 批量标记通过未修改的 1015 `ReviewSession.record` 准备，**没有声称逐条点击 170 个对象**。随后在真实 1015 复核界面确认 170/170 已复核、保留 6、剔除 164，并点击“应用复核结果”。界面确认正式变化、长时序和评价更新完成。
4. 关闭 1015，使用当前版打开同一副本，仍只重跑上述一对。
5. 重跑成功后进入当前版人工复核界面，核对实际状态及落盘草稿。没有为了通过测试而将新版待复核对象重新标记。

## 修复范围

局部重跑不再删除选中变化对的已发布矢量和 `人工复核` 目录。正式变化由后续发布替换，历史版本和草稿保留。

复核判断按完整规范化几何、变化类型和宽度属性恢复，不按行号或重新生成的 change_id 恢复。新草稿和版本保存对象指纹；旧版本利用不可变的 original_changes.shp 匹配。旧格式未应用草稿在覆盖候选前保存源矢量快照。

只对一一对应、内容未变的对象恢复判断。变化、新增、拆分、合并及重复歧义对象待复核。恢复判断作为待应用草稿展示，点击“应用复核结果”后通过原有发布事务更新正式成果、长时序和评价。

拷贝项目造成影像路径签名改变时，对没有独立候选层的旧成果核对已发布快照后打开完整原对象集，包含已剔除对象。公开 CLI 和 manifest 格式不变；复核 JSON 增加可选 feature_keys 字段。

## 1015 缓存兼容性

- 两版 `FORMAL_ROAD_REVISION` 均为 2；`is_formal_result`、`formal_products_current`、`product_cache.py`、`fast_pipeline.py` 一致。
- 正式道路模块只有异常审计 source_ids 处理修复，没有提升成果版本。
- 新增回归模拟旧安装位置及旧代码签名，禁止再次调用导出，确认完整有效的同版成果可以复用。
- 缓存缺失、输入或成果签名变化、混用更早版成果时仍会触发必要重建。复核应用实际改变道路后，也可能更新受影响期次。
- 1015 的辅助几何生成和补入方式均有变化，不能把单独调整补入预算的对照当成真实 1015 升级结果。

操作入口：局部重跑 → 选择所需变化对（可选择所有区域的全部变化对）→ 道路期次为 0 → 开始重跑。完成后核查已继承判断和待复核对象，再应用复核结果。仅重建长时序不会重新应用真值辅助。
