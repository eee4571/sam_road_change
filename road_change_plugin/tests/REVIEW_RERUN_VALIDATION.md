# 局部重跑与人工复核记录验证

## 1015 原版 → 当前版：真实桌面验收

仅测试 PlugTest 副本 `project/plug_rv` 的区域 1、变化对 **20221020 → 20230222**。两轮桌面确认均为 0 个道路期次、1 个变化对。原项目不写入。

从 `dist/road_change_plugin-windows-x64-portable-1015.zip` 提取 184 个源代码、资源和入口文件，逐文件校验与压缩包字节一致。原版 GUI 和后端均从独立目录加载，共用已有 Python 运行环境。测试副本复用此前已经升级完毕的 7 期道路缓存，不将这次测试误称为从最早版本重新生成各期道路。

1. 在 1015 桌面界面选择该变化对并重跑，完成变化检测、长时序、评价和发布。
2. 按用户指定的测试规则准备复核草稿：含真值辅助区间的对象全部保留，其余全部剔除。来源通过同类型审计区间与对象的正面积相交判断，仅边界接触不算。混合来源归为含真值辅助。
3. 批量标记通过未修改的 1015 `ReviewSession.record` 准备，**没有声称逐条点击 170 个对象**。随后在真实 1015 复核界面确认 170/170 已复核、保留 6、剔除 164，并点击“应用复核结果”。界面确认正式变化、长时序和评价更新完成。
4. 关闭 1015，使用当前版打开同一副本，仍只重跑上述一对。
5. 重跑成功后进入当前版人工复核界面，核对实际状态及落盘草稿。没有为了通过测试而将新版待复核对象重新标记。

当前版界面实际显示：**已复核 164/170、保留 0、剔除 164**；提示“已恢复 164 条未变化对象的复核判断，另有 6 条待复核；旧版本仍保留”。6 个辅助相关对象的内容发生变化，没有强行继承旧判断。旧版保留 6、剔除 164 的历史版本在重跑期间逐字节保持完整。

两轮耗时分别约 **336 秒、368 秒**，均成功结束长时序和评价；没有出现“复用缓存更新单期正式成果”阶段。原 PlugTest 的 117,318 个已有文件大小和修改时间未变，测试副本的 588 个上游推理/测宽缓存文件未变。这是一个变化对的功能验证，不是对其他区域继承数量或实际精度的保证；测试标记也不是真实人工判断。

本地证据位于忽略目录 `_work/`：`1015_review_fixture.json`、`1015_review_baseline/`、`1015_to_current_comparison.json`、`current_inheritance_audit.json`、`1015_inheritance_integrity.json`。原版基准中的复核 JSON 不含新 `feature_keys`，验证覆盖旧格式记录。

## 修复范围

局部重跑不再删除选中变化对的已发布矢量和 `人工复核` 目录。正式变化由后续发布替换，历史版本和草稿保留。

复核判断按完整规范化几何、变化类型和宽度属性恢复，不按行号或重新生成的 change_id 恢复。新草稿和版本保存对象指纹；旧版本利用不可变的 original_changes.shp 匹配。旧格式未应用草稿在覆盖候选前保存源矢量快照。

只对一一对应、内容未变的对象恢复判断。变化、新增、拆分、合并及重复歧义对象待复核。恢复判断作为待应用草稿展示，点击“应用复核结果”后通过原有发布事务更新正式成果、长时序和评价。

拷贝项目造成影像路径签名改变时，对没有独立候选层的旧成果核对已发布快照后打开完整原对象集，包含已剔除对象。公开 CLI 和 manifest 格式不变；复核 JSON 增加可选 feature_keys 字段。

## 1015 缓存兼容性

- 两版 `FORMAL_ROAD_REVISION` 均为 2；`is_formal_result`、`formal_products_current`、`product_cache.py`、`fast_pipeline.py` 一致。
- 正式道路模块只有异常审计 source_ids 处理修复，没有提升成果版本。
- 新增回归模拟旧安装位置及旧代码签名，禁止再次调用导出，确认完整有效的同版成果可以复用。
- 缓存缺失、输入或成果签名变化、混用更早版成果时仍会触发必要重建。复核应用实际改变道路后，也可能更新受影响期次。
- 1015 的辅助几何生成和补入方式均有变化，不能把单独调整补入预算的对照当成真实 1015 升级结果。

操作入口：局部重跑 → 选择所需变化对（可选择所有区域的全部变化对）→ 道路期次为 0 → 开始重跑。完成后核查已继承判断和待复核对象，再应用复核结果。仅重建长时序不会重新应用真值辅助。

## 六条辅助对象保留后的评价对照（2026-10-16）

继续上述同一个测试副本、同一个变化对。在当前桌面复核界面逐条将 6 个待复核辅助相关对象标记为保留，保留原有 164 条剔除判断。点击应用后，界面确认正式变化、长时序、统计和精度评价已更新；落盘记录为 keep=6、reject=164、pending=0。

应用过程中发现并修复一次阻塞：历史已应用版本仍是旧候选签名，而草稿已经迁移至新候选，重新打开时却重复返回迁移警告，导致界面的批量应用停止。现在有效的当前签名草稿不再重复迁移；首次恢复仍提示，待应用状态仍保留，历史版本不改动。修复仅涉及 `code/app/change_review.py`，未改公开接口、检测或评价公式。

两版原生输出的统计口径不同：1015 原生查全率 90.581802%、查准率 54.631069% 是严格面积重合率；当前版原生查全率 95.001897%、查准率 62.010902% 使用 4 px 位置容差。1015 原生完整度为 0、像素偏移为空，同时预测中心线长度为 0，不能解释为真实道路完整度为零或偏移为零。

为比较成果本身，另行在忽略目录中用当前版评价函数，对两版各自已发布的 6 个对象做只读重算。两次使用同一真值、验证范围、真实前期影像网格及 4 px 容差，均纳入全部 5 条真值，没有排除真值。新版本重算的五项指标与桌面发布 CSV 精确一致。

| 同一当前评价口径 | 1015 成果 | 新版成果 |
| --- | ---: | ---: |
| 查全率 | 97.768088% | 95.001897% |
| 查准率 | 62.756497% | 62.010902% |
| 道路中心线完整度 | 78.295455% | 77.159091% |
| 中心线平均偏移 | 18.435724 px | 19.369734 px |
| 变化类型准确率 | 100% | 100% |

这是按用户指定规则构造的复核测试：含辅助来源的 6 条保留，其余 164 条剔除，不代表真实逐对象判读后的项目精度。新版该对查全率落在 93%–96%，但中心线偏移未达到 4 px，不能称为各项全部达标。原始严格面积查全率在新版为 89.277414%，用于与容差查全率区分。

其他 5 个变化对的 manifest 条目与旧版基准完全一致；588 个上游缓存文件的大小和修改时间未变。旧版复核历史 JSON 仍与基准逐字节一致。仅更新一对后，总体查全率/查准率因其他变化对尚无同口径容差指标而显示未评价；没有将不同口径混算或重跑另外 5 对。

新增回归覆盖：恢复旧记录 → 修改并自动保存待复核对象 → 重新打开 → 无重复警告/归档 → 保持待应用 → 成功发布。19 项 `check_change_review.py` 测试和真实 Qt/后端 `check_review_process.py` 集成检查通过，语法与 diff 检查通过。本地复算脚本和完整数值证据：`_work/compare_review_metrics.py`、`_work/review_metrics_comparison.json`。
