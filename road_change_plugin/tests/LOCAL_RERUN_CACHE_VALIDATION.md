# 局部重跑缓存修复与核查（2026-10-13）

## 用户操作

更新插件并重新启动 PySide 程序后，在原有局部重跑页面只选择所需变化对即可。
后端先检查两期及所需相邻期，复用已有道路、概率和原始测宽缓存更新过期正式成果，再执行变化检测。区域长时序依赖的其他期次也只在正式导出过期时补做导出。
不增加导出按钮或新复核流程；日志会显示“复用缓存更新单期正式成果”。
缓存缺失时明确指出期次并要求重跑该道路期次，不会在“只重跑变化对”时自动启动模型推理。

## 核查发现与修改

| 原问题 | 修改后 |
| --- | --- |
| PySide 局部期次重跑删除整个期次工作目录 | 保留推理、概率、测宽和阶段断点，只清理对应发布成果及选中变化输出 |
| 后端每次创建 `roads_rerun_<时间>` 目录 | 复用原运行目录，开启阶段续跑；失败重试沿用同一路径 |
| 变化重跑直接拒绝旧正式产品版本 | 自动补做必要正式导出，更新结果索引；导出完成但索引未保存的重试也能恢复 |
| 只改导出或变化检测代码，也让测宽缓存失效 | 用测宽函数及同模块依赖的代码身份替代整个 `fast_pipeline.py` 身份；保留测宽实现、参数及输入校验 |
| 输入变化或阶段重跑后，下游失效状态只存在内存中 | 执行阶段前持久化下游 pending；停止在两阶段之间也不会错用旧成果 |
| 更换测宽方法只标记导出失效 | 从测宽阶段开始更新；影像、模型和配置变化从推理阶段校验；有效图片仍走原逐图缓存 |
| 仅补导出也无条件重建概率拼接和有效观测面 | 未重跑相关上游阶段且已有文件完整时复用 |
| 旧单期/变化命令失效整个项目下游 | 与批量选择一样，只处理受影响区域和变化对 |
| 更新一组变化会重新发布同区域其他变化，清除人工复核状态 | 已完成的未选变化、复核决定和评价保留；当前版本的未重跑正式道路保留 |
| 评价失败后重试再次失效所有几何 | 保留已完成几何，只重试待完成评价；区域长时序按依赖更新 |

`rerun-period`、`rerun-change`、`rerun-selection` 及批量命令参数不变。批量选择继续按依赖去重；完成步骤保持断点，不重复推理。
完整重算的既有含义不变。旧缓存首次补齐新增身份信息时可能重新进入逐图缓存校验；输入或算法确实变化时仍会重算相应阶段，不能承诺所有旧项目的期次重跑都完全零计算。
